# AI evaluation for the demo

Run the optional Compose evaluation profile to generate `ai_eval/eval_report.json` and `ai_eval/eval_report.md` in the repository. The Markdown report is intended for a demo or judge walkthrough.

Development checks use 60 baseline synthetic examples, an 80-case multilingual category stress set, and a separate 200-case fictional scenario set. The 80-case stress set contains 40 English examples and 20 each in Hindi and Kannada; the Hindi and Kannada examples are draft translations, not native-reviewed. The 200-case set has 40 English examples for each of five investigation scenarios, with 32 positive and 8 non-threat examples per scenario. Run `python -m ai_eval.run_dev_eval` to evaluate all development sets; it does not read private cases or the held-out challenge set. The judge report also includes a separate 28-case synthetic challenge suite, which remains held out from tuning. The challenge suite covers five investigation themes and hard negative examples across English, Hindi and Kannada. It also runs four generated OCR fixtures. All project-authored synthetic labels are development checks, not independent review or real-world accuracy evidence; they cannot establish screenshot authenticity, image manipulation, or deepfake detection.

Before making real-world performance claims, create a separate evaluation set from evidence that is consented for evaluation and de-identified. Two reviewers should label each item independently, without seeing each other’s labels or the model result. Record each reviewer’s threat/no-threat label and `expected_categories` list in `reviewer_labels`; use an empty list for no threat and one or more supported labels for a threat. If labels disagree, have a third reviewer, listed separately as `adjudicator_id`, adjudicate and record final `expected_threat`, `expected_categories`, and `adjudicated_threat`/`adjudicated_categories`. The evaluator reports aggregate reviewer agreement and binary threat-detection counts by scenario, language and media type, plus multi-label category metrics by category, language, scenario and media type. It does not verify consent or reviewer independence. Keep this evaluation set out of rule tuning. Tune only against the separate development examples, then evaluate once against the held-out challenge set. Do not publish source evidence, reviewer identities or identifying details. For an exploratory pilot, aim for at least five positive and five non-threat examples in each of the five core scenarios; this is still too small to claim reliable real-world performance.

Analysis results are triage leads for human review. They are not proof of authenticity, determinations of criminal conduct or criminality predictions.

## Local consented evaluation workflow

The evaluator accepts `ai_eval/private_cases.jsonl` and files under `ai_eval/private_assets/`. Both locations are ignored by Git. Begin from `ai_eval/private_cases.example.jsonl`; use random IDs, remove identifying details, and include only data with documented consent or a license that permits this use. Each row must include two distinct reviewer IDs, a non-identifying consent reference (or, for licensed public data, the source reference and license), a language, a scenario label, and independently reviewed threat/no-threat and category labels. Category names are `cyberstalking_bullying`, `blackmail_threatening`, `intimate_image_abuse`, `defamation_morphing`, `fake_profile_impersonation`, and `other`. A no-threat example has an empty category list; if a threat does not fit the five main categories, label it `other`. A row may use a reviewed transcript or a local PNG/JPEG/PDF path. For OCR scoring, include the independently reviewed `expected_text`.

The 200-case `ai_eval/fictional_scenario_set.jsonl` is generated by `ai_eval/build_fictional_scenario_set.py`. It contains only author-written fictional message/context excerpts, including non-threat examples. Its labels are not independent reviewer labels. Use it to inspect behavior and regressions in the five workflows; do not describe its scores as measured user accuracy or as evidence that a file, account, or allegation is authentic.

Run the existing Compose evaluation profile. The report stores aggregate counts and metrics only; it does not include private text or file paths. The evaluator measures configured local rules and OCR; it does not call the optional LLM. Keep the private dataset out of screenshots, commits, and judge submissions. A small or convenience sample is not representative; report its size and source limits.


## Blind annotation and development-only checks

Use `ai_eval/annotation-guide.md` with `prepare_annotations.py` and `merge_annotations.py` to create separate reviewer sheets and merge consensus/adjudicated labels locally. The scripts do not upload evidence or print case content. `python -m ai_eval.run_dev_eval` evaluates the synthetic baseline, category stress set, and fictional scenario set; it does not read the private set or the held-out challenge set.
